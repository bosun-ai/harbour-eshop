# Opt-In HTTPS Gateway

Harbour owns every route and all application state. This separate executable is
an all-proxy bootstrap, not an application migration or a production deployment.
Building or merging it does not change the root Dockerfile or default launch.

## Build And Run

```sh
cargo build --locked --release --manifest-path gateway/Cargo.toml
cargo run --locked --manifest-path gateway/Cargo.toml -- serve
docker build -f gateway/Dockerfile -t eshop-gateway gateway
```

Supply these environment variables to both `serve` and `probe live|ready`:

| Variable | Rule |
| --- | --- |
| `GATEWAY_BIND` | Socket address, default `0.0.0.0:8002`, nonzero port |
| `LEGACY_UPSTREAM_URL` | Required HTTPS origin; no credentials, base path, query or fragment |
| `GATEWAY_TLS_CERT_FILE`, `GATEWAY_TLS_KEY_FILE` | Required readable PEM pair; validated before listen |
| `LEGACY_TLS_CA_FILE` | Required explicit PEM trust bundle; hostname/chain verification always enabled |
| `GATEWAY_ACTIVE_FAMILIES` | Empty by default; bootstrap rejects any ID |
| `GATEWAY_CONNECT_SECONDS` | 5 by default; includes DNS, TCP and TLS |
| `GATEWAY_EXCHANGE_SECONDS` | 180 by default; includes upload and response streaming |
| `GATEWAY_DRAIN_SECONDS` | 30 by default; then remaining public connections are aborted |
| `GATEWAY_LOG_LEVEL` | Valid tracing level, default INFO |

All timeouts accept integer seconds in 1..=3600. Certificates are supplied, never
generated by the gateway. The legacy generated CN-only certificate is unsuitable
for verified upstream TLS: supply a DNS SAN matching the configured hostname.
Files must be readable by container UID 65532. `probe live` checks the local TCP
listener; `probe ready` also checks verified upstream `GET /hello` is `200 Hello!`.
No public path is reserved for health checks. Startup can precede Harbour;
readiness must fail until Harbour is reachable and trusted.

## Contract And Extension Point

HTTP/1 only. Methods, raw path/query, original Host, cookies, end-to-end fields,
separate Set-Cookie fields, Location, status and bytes remain opaque. Connection
and nominated hop fields are removed. No forwarded metadata is injected, no
redirect is followed, no request is retried (including stateful shopping GETs).
Each request has its own verified upstream connection. Known-length bodies are
streamed with backpressure. Chunked bodies stay chunked: the legacy parser does
not support chunked forms; this gateway does not buffer them into successful
commands. HTTP syntax validation belongs to Hyper; unrestricted malformed-wire
compatibility is not promised. No compression or HTML rewriting is performed.

Pre-header transport failures produce 502; deadlines produce 504. Failed bodies
after headers terminate the connection and log a category, not a replacement
response. Completed length-framed legacy responses are accepted even if the
peer omits TLS close_notify; truncated bodies remain errors. SIGINT/SIGTERM stops
accepting and drains boundedly. At most 256 public connections are accepted;
TLS handshakes and upstream drivers have bounded deadlines. Logs contain only
gateway correlation, owner, method, status, duration and fixed categories. This
does **not** redact Harbour's existing request/body tracing.

Public HTTP/1 keep-alive is disabled: each response explicitly closes its
connection, so later requests cannot inherit an older connection's deadline.
Connections also have a maximum lifetime of exchange + connect seconds,
bounding idle clients and blocked downstream writes. A timeout error response
gets a separate connect-sized send window. This policy must be checked against
actual browser transfer workloads.

Future slices implement `dispatch::Handler`, add one complete `Family`
registration in the composition root, and require explicit activation. Families
declare complete path subtrees and method policies. Registration does not
activate them. Unknown/duplicate IDs, incomplete registrations and overlapping
active subtrees fail before listen. Unknown paths/methods still go to Harbour.
No domain logic belongs in transport or dispatch modules.

## Opt-In Docker Topology

Prerequisites: public certificate delivery for the browser hostname, an upstream
SAN certificate and explicit trust, Docker daemon access, and checked retention
of the **current complete** `/app` runtime. Record the legacy image digest
(`docker image inspect --format '{{.Id}}' harbour-eshop`) and actual runtime-state
location; base image tags and package resolution remain mutable. Quiesce Harbour
with `./eshop //stop` and snapshot/check its full state, not tracked empty DBFs.
Recreation loses process-memory sessions (600-second sliding timeout normally).

Example for a **new disposable dataset only** (existing data requires deliberate
transfer and validation):

```sh
docker network create eshop-private
docker volume create eshop-state
docker create --name legacy --network eshop-private --network-alias legacy \
  -v eshop-state:/app harbour-eshop
# docker create initializes /app from the image. Copy SAN=legacy PEMs before start.
docker cp private.crt legacy:/app/certificate.crt
docker cp private.key legacy:/app/private.key
docker start legacy                         # NO -p on Harbour
docker create --name gateway --network eshop-private -p 8002:8002 \
  -e LEGACY_UPSTREAM_URL=https://legacy:8002 \
  -e LEGACY_TLS_CA_FILE=/tmp/trust.crt \
  -e GATEWAY_TLS_CERT_FILE=/tmp/public.crt \
  -e GATEWAY_TLS_KEY_FILE=/tmp/public.key eshop-gateway
docker cp upstream-ca.crt gateway:/tmp/trust.crt
docker cp public.crt gateway:/tmp/public.crt
docker cp public.key gateway:/tmp/public.key
docker start gateway
docker exec gateway eshop-gateway probe ready
```

Production certificate delivery should use separate read-only mounts (existing
paths on the **daemon host**); only public upstream trust reaches Rust, never the
Harbour private key or `/app`. `docker cp` supports remote-daemon disposable
verification without client-local bind assumptions. Only gateway publishes
8002. If the private network is `--internal`, attach gateway to a separate edge
network. Empty activation plus passing readiness and acceptance is mandatory
before traffic restoration. Do not run two Harbour writers on one volume.

## Rollback

Stop/drain gateway and release host 8002. Stop private Harbour using its existing
`./eshop //stop`, wait for exit, then remove its container. Recreate the recorded
legacy image with the **same current** `/app` volume and `-p 8002:8002`. Before
start, restore certificate/key valid for the public hostname (not upstream-only
SAN). Verify `/hello`, reauthentication, persisted account and cart. Do not
replace current writes with a stale snapshot or empty image tables. No data
conversion is needed; session loss and bounded interruption are expected.
Future Rust-owned mutable data requires its own rollback contract.

## Verification

```sh
cargo test --locked --manifest-path gateway/Cargo.toml
cargo fmt --check --manifest-path gateway/Cargo.toml
cargo clippy --locked --manifest-path gateway/Cargo.toml --all-targets -- -D warnings
sh verification/gateway.sh
sh verification/coverage.sh
```

The harness builds both real images, uses verified TLS and independent disposable
volumes/cookie jars, compares protocol/browser behavior, and rehearses isolation,
restart and rollback. Traps remove containers, volumes, networks and temporary
certificates on success or failure; application traces are not printed. Images
remain reusable build outputs, not deployments. Timeout values are policy gates:
validate larger real uploads/response sizes and environment latency before
production activation. No account/credential/money/datastore migration, session
sharing, certificate rotation, metrics platform or deployment automation is
included.

`coverage.sh` measures LLVM 22 native **counter** coverage, without installing
tools. CI pins Rust 1.97.1 (LLVM 22.1.6) to match the raw-profile reader; validate
the reader before upgrading the CI compiler. It fails on unsupported profile
formats rather than claiming line/branch coverage; a different compiler needs
its matching LLVM report tools or an updated reader. Unit tests exercise
activation decisions and header filtering; the
instrumented local fault corpus exercises adapter and lifecycle success/failure
paths. Container parity uses the real release image separately.
